# 低表现文案定位 — 用户配置

## Skill 功能说明

这个 skill 用于定位需优化文案并插入空行。

从 KPI 后台查询低表现广告素材（表现为 `Low` 或 `Learning` 的末三位），在 Google Sheets 对应工作表中插入格式正确的空白优化行。**此 skill 不填写优化内容**，只建立行结构，供后续流程或人工填写。

---

此文件由 skill 在每次任务开始时读取。首次使用时告诉 Agent "帮我配置低表现文案定位"，Agent 会通过对话引导你填写下方各项。

**当前自动生效的配置**：
- ✅ `字段名映射` — `sync_low_assets.py` 启动时直接解析，把"你的表格标题"列作为别名加入识别

**仅 Agent 阅读，脚本暂未自动应用**（Agent 应按这些设置调整自己的行为或调用方式）：
- 📖 `前置检测` — Agent 在三项检测未通过时停止流程
- 📖 `数据查询` — Agent 据此选择 `--query-window` 或 `CODEX_TODAY`
- 📖 `需要登记的字段` / `筛选规则` / `写入行为` / `摘要区域` / `其他偏好` — 当前脚本行为已硬编码为这些设置，改这里不会改变运行结果

## 前置检测（每次任务开始时自动执行）

**在执行任何筛选或写入操作前，必须按顺序完成以下三项检测。若任意一项未就绪，停止当前任务并引导用户完成对应步骤，完成后再继续。**

### 检测一：chrome-launcher-with-userdata 是否已安装

检测方式：尝试调用 `/chrome-launcher-with-userdata` skill。若 skill 不存在或无法触发，判定为未安装。

未安装时的引导步骤：
1. 提示用户：「需要先安装 chrome-launcher-with-userdata skill，请按以下步骤操作：」
2. 在中台（SkillMan）下载客户端并安装
   - Mac 用户安装后需执行：`xattr -rd com.apple.quarantine /Applications/SkillMan.app`
3. 打开 SkillMan → 点击「发现 SKILL」→ 搜索 `chrome-launcher-with-userdata` → 安装
4. 点击「链接到 Claude Code」（或「链接到 Codex」）
5. 完成后重新触发当前任务

已安装时：继续检测二。

---

### 检测二：KPI 登陆态是否有效

检测方式：检查本 skill 目录中是否存在 `kpi_session.json`，并读取其中的 Cookie（需包含 `_csrf-backend`、`PHPSESSID`、`_identity-backend` 三个必需 Cookie）。**文件存在且 Cookie 字段完整，直接复用，无需重新抓取**；文件不存在或 Cookie 字段缺失时，才走下方的重新抓取流程。不再以文件修改时间作为判断依据。

无效或不存在时的引导步骤：
1. 提示用户：「需要先获取 KPI 登陆态，即将启动 Chrome。」
2. 调用 `/chrome-launcher-with-userdata` 启动 Chrome，获取 CDP URL
3. 首次使用注意：
   - 启动前需关闭所有 Chrome 窗口
   - 首次启动后如 Google 账号显示停用，需手动登录一次
   - 在 Chrome 中手动访问并登录 KPI 后台（`https://kpi.drojian.dev`），后续不再需要
4. Chrome 启动成功后，运行：
   ```bash
   python3 scripts/capture_kpi_cookie_cdp.py \
     --cdp-url "<CDP_URL>" \
     --session-json-out <skill目录>/kpi_session.json
   ```
5. 脚本输出 `cookies_ready_but_unverified` 或 `ok` 均视为成功；输出 `logged_out` 则提示用户先在 Chrome 中登录 KPI 后台后重试
6. 完成后继续检测三

已有效时：继续检测三。

---

### 检测三：app-id-map.json 是否已填写

检测方式：读取 `references/app-id-map.json`，若文件不存在或内容为空对象 `{}`，判定为未配置。

未配置时（**Agent 自动执行，无需等待用户指令**）：
1. 通知用户：「app-id-map.json 为空，正在从 KPI 后台解析你的权限列表并写入本地…」
2. 确认 KPI session 已就绪（检测二已通过）
3. 自动执行：解析当前账号在 KPI 后台有权限的所有 app，将 `{"app名称": app_id, ...}` 写入 `references/app-id-map.json`
4. 写入完成后，展示解析结果，提示用户：「若有不需要的 app，可告知 Agent 删除对应条目」
5. 继续执行后续步骤（无需用户额外确认）

已配置时：直接继续。

---

### 三项检测全部通过后：询问本次目标 App

三项检测均通过后，**在执行任何筛选操作前**，必须向用户询问：

> 「本次任务要执行的 App name 是什么？」

展示 `references/app-id-map.json` 中已有的 app 名称供用户选择或输入。用户确认后继续执行筛选任务。
